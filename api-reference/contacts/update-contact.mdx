The Update Contact endpoint modifies one or more fields on an existing contact record. Send only the fields you want to change — any field you omit stays exactly as it is. To erase a field's current value, send it explicitly as `null`. This endpoint requires the `contacts:write` scope and an `Idempotency-Key` header on every request.

## Endpoint

```http
POST https://api.scopable.io/v1/contacts/{contactId}
```

## Required Headers

| Header | Description |
|---|---|
| `Authorization` | `Bearer <your-api-key>` |
| `Content-Type` | `application/json` |
| `Idempotency-Key` | A unique string that makes this request safe to retry. |

## Path Parameters

<ParamField path="contactId" type="string" required>
  The UUID of the contact to update. Must belong to your Scopable tenant.
</ParamField>

## Request Body

All fields are optional. Include only the fields you want to change.

<ParamField body="name" type="string">
  Updated full name of the contact. Send `null` to clear the value.
</ParamField>

<ParamField body="email" type="string">
  Updated email address. Send `null` to clear the value.
</ParamField>

<ParamField body="phone" type="string">
  Updated phone number. Send `null` to clear the value.
</ParamField>

<ParamField body="title" type="string">
  Updated job title. Send `null` to clear the value.
</ParamField>

<Note>
  Sending a field as `null` clears its stored value. Omitting a field entirely leaves its current value unchanged. These are two distinct operations.
</Note>

## Example Request

```bash
curl -X POST "https://api.scopable.io/v1/contacts/abc123" \
  -H "Authorization: Bearer $SCOPABLE_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: update-ada-title-001" \
  -d '{"title":"Technical Director"}'
```

## Additional Contact Actions

Beyond updating fields, three additional POST endpoints let you manage a contact's status and default assignment:

<CardGroup cols={3}>
  <Card title="Set as Default" icon="star">
    **`POST /v1/contacts/{contactId}/set-default`**

    Promotes this contact to the client's primary contact, demoting any existing default. Requires `contacts:write` scope.
  </Card>
  <Card title="Archive Contact" icon="box-archive">
    **`POST /v1/contacts/{contactId}/archive`**

    Hides the contact from active views and clears its default-contact flag if set. See [Archive & Restore](/api-reference/contacts/archive-restore-contact).
  </Card>
  <Card title="Restore Contact" icon="rotate-left">
    **`POST /v1/contacts/{contactId}/restore`**

    Brings an archived contact back to active status. See [Archive & Restore](/api-reference/contacts/archive-restore-contact).
  </Card>
</CardGroup>

All three action endpoints require an `Idempotency-Key` header and the `contacts:write` scope. Pass an empty JSON object (`{}`) as the request body.

## Error Responses

| HTTP Status | Error Code | Meaning |
|---|---|---|
| `400` | `validation_failed` | One or more field values failed validation. |
| `401` | `unauthorized` | Missing or invalid API key. |
| `403` | `forbidden` | Your API key does not have the `contacts:write` scope. |
| `404` | `not_found` | No contact with that ID exists in your tenant. |
| `409` | `conflict` | A request with the same `Idempotency-Key` was already completed with a different body. |
| `429` | `rate_limited` | You have exceeded 60 write requests per minute. |
| `503` | `unavailable` | Scopable is temporarily unavailable — retry with backoff. |
