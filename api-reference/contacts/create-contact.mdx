---
title: "POST /v1/contacts — Create a Contact"
sidebarTitle: "Create Contact"
description: "Create a new contact under a specified client. If the client has no default contact yet, the newly created contact is automatically set as default."
---

The Create Contact endpoint adds a new contact to an existing Scopable client. You must supply a `clientId` and the contact's `name` at minimum; `email`, `phone`, and `title` are optional. If the target client has no default contact at the time of creation, Scopable automatically promotes the new contact to the default position. This endpoint requires the `contacts:write` scope and an `Idempotency-Key` header on every request.

## Endpoint

```
POST https://api.scopable.io/v1/contacts
```

## Required Headers

| Header | Description |
|---|---|
| `Authorization` | `Bearer <your-api-key>` |
| `Content-Type` | `application/json` |
| `Idempotency-Key` | A unique string that makes this request safe to retry without creating duplicate contacts. |

## Request Body

<ParamField body="clientId" type="string" required>
  UUID of the Scopable client this contact belongs to.
</ParamField>

<ParamField body="name" type="string" required>
  Full name of the contact.
</ParamField>

<ParamField body="email" type="string">
  Email address of the contact. Optional, but strongly recommended to support deduplication in your integration.
</ParamField>

<ParamField body="phone" type="string">
  Phone number of the contact.
</ParamField>

<ParamField body="title" type="string">
  Job title of the contact.
</ParamField>

<Warning>
  Scopable does not deduplicate contacts by email on create. If your integration might send an existing contact, use [Search Contacts](/api-reference/contacts/search-contacts) first to check whether a contact with that email already exists before calling this endpoint.
</Warning>

## Example Request

```bash
curl -X POST https://api.scopable.io/v1/contacts \
  -H "Authorization: Bearer $SCOPABLE_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: contact-ada-lovelace-001" \
  -d '{"clientId":"3f0c2a4e-8d1b-4c6a-9e2f-5b7d1a0c9e84","name":"Ada Lovelace","email":"[email protected]"}'
```

<ResponseField name="contact" type="object" required>
  The newly created contact object.

  <Expandable title="contact fields">
    <ResponseField name="id" type="string" required>
      Unique UUID identifier for the contact within Scopable.
    </ResponseField>

    <ResponseField name="clientId" type="string" required>
      UUID of the client this contact belongs to.
    </ResponseField>

    <ResponseField name="name" type="string" required>
      Full name of the contact.
    </ResponseField>

    <ResponseField name="email" type="string | null">
      Email address of the contact.
    </ResponseField>

    <ResponseField name="phone" type="string | null">
      Phone number of the contact.
    </ResponseField>

    <ResponseField name="title" type="string | null">
      Job title of the contact.
    </ResponseField>

    <ResponseField name="isDefault" type="boolean" required>
      Whether this contact is the client's default (primary) contact. Automatically `true` if the client had no default contact at the time of creation.
    </ResponseField>

    <ResponseField name="archivedAt" type="string | null">
      Always `null` for a newly created contact.
    </ResponseField>

    <ResponseField name="createdAt" type="string" required>
      ISO 8601 timestamp of when the contact was created.
    </ResponseField>

    <ResponseField name="updatedAt" type="string" required>
      ISO 8601 timestamp of the most recent update. Equals `createdAt` for a new contact.
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
  If the client had no default contact when you created this one, Scopable automatically sets `isDefault: true` on the new contact. You can also explicitly set a different contact as default at any time using the [set-default](/api-reference/contacts/archive-restore-contact) endpoint.
</Note>

## Idempotency

Pass a stable, unique `Idempotency-Key` that identifies this specific create operation (e.g., `contact-ada-lovelace-001`). If your request fails in transit and you retry with the same key, Scopable returns the originally created contact rather than creating a duplicate.

## Error Responses

| HTTP Status | Error Code | Meaning |
|---|---|---|
| `400` | `validation_failed` | Required fields are missing or values failed validation. |
| `401` | `unauthorized` | Missing or invalid API key. |
| `403` | `forbidden` | Your API key does not have the `contacts:write` scope. |
| `404` | `not_found` | The supplied `clientId` does not exist in your tenant. |
| `409` | `conflict` | A request with the same `Idempotency-Key` was already completed with a different body. |
| `429` | `rate_limited` | You have exceeded 60 write requests per minute. |
| `503` | `unavailable` | Scopable is temporarily unavailable — retry with backoff. |
